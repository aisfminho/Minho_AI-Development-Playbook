## B. 일반화 템플릿

### B-1. 인계 문서 (`AGENT_HANDOFF.md`)

```markdown
# AGENT_HANDOFF — {날짜 시각}

## 지금 상태
- 단계: {설계 / STEP-XX}
- 마지막 커밋·태그: `{hash}` / `{tag}` (push 여부: {예/아니오})
- 승인 대기: {무엇을, 어떤 명령으로}

## 다음 세션이 먼저 읽을 것 (순서대로)
1. {헌장 문서}
2. {PROJECT_CONTEXT.md}
3. {결정 기록 — 최근 D-xxx}
4. {감사 상태표 — 차단 조건 열}

## 하지 말 것
- 승인 없이 구현·push·배포·유료 호출
- {채널 분리 파일} 읽기
- {기타}

## 첫 행동
{예: 상태 확인 후 "STEP-XX 시작 승인"을 기다린다}

## 이전 세션
- {세션 ID 앞 8자리}: {한 줄 요약}
```

### B-2. 새 세션 시작 프롬프트

```markdown
이어서 작업합니다. 먼저 `{AGENT_HANDOFF.md}`와 `{PROJECT_CONTEXT.md}`를 읽고,
현재 단계·승인 대기 사항·하지 말 것을 3~5줄로 요약해 주세요.
요약이 인계 문서와 다르거나 작업 트리가 예상과 다르면 작업하지 말고 먼저 보고해 주세요.
```

### B-3. 세션 종료 전 요청

```markdown
컨텍스트 관리를 위해 새 세션으로 넘어가려 합니다.
1. `{PROJECT_CONTEXT.md}`를 실제 변경 기준으로 갱신
2. `{AGENT_HANDOFF.md}`에 지금 상태·첫 행동·하지 말 것 작성
3. 새로 생긴 규칙은 메모리에 "규칙 + 이유 + 적용법"으로 기록
4. 커밋은 하지 말고 변경 파일 목록만 보고
```

### B-4. 구현 전 기준 태그 요청

```markdown
커밋 `{hash}`을 구현 착수 전 기준점으로 확정합니다. 다음을 순서대로 하고 각 결과를 보고하세요.
1. 로컬 HEAD·로컬 main·원격 main이 `{hash}`인지 확인(원격은 새로 fetch)
2. 같은 이름 태그 `{tag}`가 로컬·원격에 없는지 확인
3. `{hash}`에 annotated tag `{tag}` 생성
4. 태그만 push
5. 원격 태그가 `{hash}`를 가리키는지 검증
강제 push, 태그 덮어쓰기, 다른 브랜치·파일 변경은 하지 마세요. 인계 문서 갱신은 별도로 승인합니다.
```
