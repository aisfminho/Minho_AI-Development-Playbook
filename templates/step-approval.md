# 템플릿: STEP 계획과 승인

## A. 실사용 원문 (발췌)

- 승인 명령어: `STEP-XX 시작 승인` = 그 Step 구현 시작 / `STEP-XX 완료 승인` = 마무리하고 다음 Step의 **계획만** 제시 / `STEP-XX 반려` = 수정. "어떤 경우에도 제 승인 없이 다음 Step으로 넘어가지 마세요"(memory `step-approval-process.md`, 세션 `44d22df7`)
- 완료 중심: "날짜별 개발 일정을 강제로 지키기보다 기능을 완료하는 즉시 다음 작업으로 진행 … 기존 Step별 시작·완료 승인 체계는 유지"(`55b37226:473`)
- 최소 단위 표 항목: `선행 | 범위 | 자동 테스트 | 완료 기준 | AUD·TP 연결`, "실패한 단위는 완료로 표시하지 않고, 의존 단위는 시작하지 않는다", "'통과' 주장은 실제 실행 출력 인용"(memory `testable-minimal-units.md`, 세션 `bab8244b`)

## B. 일반화 템플릿

### Step 계획서

```markdown
# STEP-{XX} {이름} — 계획

- 상태: 계획 제시 / 시작 승인 대기
- 목적: {이 Step이 끝나면 무엇이 가능해지나}
- 선행 조건: {선행 Step, 필요한 결정 ID}
- 범위: {포함} / 범위 밖: {제외}
- 별도 승인 필요 행동: {유료 호출, 배포, push 등. 없으면 "없음"}

## 최소 단위
| 단위 | 선행 | 범위(한 가지 동작) | 자동 테스트 | 완료 기준 | 감사·테스트 연결 |
|---|---|---|---|---|---|
| {XX-01} | — | {동작} | {테스트 이름, Mock 사용 여부} | {관찰 가능한 기준} | {AUD-xx, TP-xx} |

## 완료 조건
- [ ] 모든 단위의 테스트가 실제 실행에서 통과
- [ ] 회귀 테스트 통과
- [ ] 독립 리뷰 지적 반영
- [ ] 사용자 검증 방법 안내

승인 명령: "STEP-{XX} 시작 승인"
```

### Step 완료 보고

```markdown
# STEP-{XX} 완료 보고
| 단위 | 결과 | 근거(실행 출력 요약) |
|---|---|---|
| {XX-01} | 통과 | `{N} passed` |
- 남은 위험: {…}
- 사용자 확인 방법: {명령 또는 화면 경로}
- 다음 승인: "STEP-{XX} 완료 승인" 또는 "STEP-{XX} 반려"
- 다음 Step 계획: (완료 승인 후 제시)
```

### 헌장 문서에 넣을 문장

```markdown
## 승인 규칙
- 현재 단계: {설계 / STEP-XX 구현}
- 승인 명령어 외의 표현("진행해 줘" 등)은 다음 Step 승인이 아니다. 확인 질문을 한다.
- 별도 승인: 최초 유료 호출, 데이터 재수집, 외부 배포, commit/push/tag, 원문 출력
- 이미 올라간 Git 이력은 다시 쓰지 않는다.
```
