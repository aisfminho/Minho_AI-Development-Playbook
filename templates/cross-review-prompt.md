# 템플릿: 다중 AI 중계 검토 (교차 검토 프롬프트)

AI끼리 자동으로 연결되지 않는 환경에서, **사람이 한 AI의 보고를 다른 AI에 전달해 검토시키는** 절차의 양식입니다. MOEL AI에서는 Claude Code의 보고를 ChatGPT에 붙여넣어 검토받고, ChatGPT가 쓴 지시문을 다시 Claude Code에 붙여넣었습니다([05-chatgpt.md](../case-studies/moel-ai/05-chatgpt.md) 1·4절).

## A. 실사용 원문 (발췌)

**검토자(ChatGPT)가 자기 범위를 밝힌 문장** (`gpt:6af696c2/2e1486a5`, 11-13)

> 다만 아직 `respond.md` 원문과 실제 변경된 설계 문서를 내가 직접 대조한 것은 아니므로, 최종 검증까지 완료됐다고 판단하지는 않을게.

**방향 승인과 최종 승인을 나눈 문장** (`gpt:6af696c2/6ef88671`, 11-13)

> 설계 방향 승인과 최종 디자인 승인은 구분하는 것이 좋겠어. 아직 실제 A+ 목업을 내가 보지 못했기 때문에, 화면의 완성도까지 판단할 수는 없거든.

**전부 승인하지 않고 항목별로 판단한 사례** (`gpt:6af696c2/8bc0bf8e`)

> 4개 결정은 모두 조건부 승인하되, 실제 디자인은 A+ 목업을 보고 최종 확정하는 것을 추천해.

**검토 결과를 출처와 함께 기록하라는 지침** (`gpt:6af696c2/0a2b664e`의 문안 일부)

> AUD-02·12·13·16의 최종 PASS는 사용자가 전달한 Codex 최종 검증 결과를 근거로 기록합니다. Claude Code가 직접 독립 재검증한 것처럼 표현하지 마세요.

**한 번에 하나의 AI에게만 지시** (`gpt:6af696c2/98b12776`)

> 지금 새로운 설계 감사 프롬프트까지 보내면 Claude Code가 여러 요구사항을 동시에 처리하면서 설계 범위가 계속 확장될 수 있어. … 기존에 Claude Code에 요청한 작업의 답변부터 처리하는 것을 추천해.

## B. 일반화 템플릿

### B-1. 검토를 맡길 때 (사용자 → 검토 AI)

```
[중계 검토 요청]
- 보고를 낸 AI: {Claude Code / Codex / 다른 AI}
- 보고 시각·단계: {YYYY-MM-DD HH:MM, STEP-XX}
- 보고 원문: (아래에 붙여넣음. 요약하지 않음)
- 당신이 볼 수 있는 것: 붙여넣은 텍스트만 / 첨부 파일 {목록}
- 당신이 볼 수 없는 것: 원본 파일·코드·실행 결과 (해당하면 명시)
- 요청: 항목마다 다음 중 하나로 판단하세요.
  승인 / 조건부 승인(조건) / 반려(이유) / 확인 불가(필요한 자료)
- 구분해 주세요: 보고에 적힌 사실 / 당신의 추정 / 확인하지 못한 것
- 다음 지시문 초안: {요청함 / 요청하지 않음}  ← 기본값은 "요청하지 않음". 검토만 하고 지시문은 쓰지 마세요.
  ("요청함"으로 바꾼 경우에만 B-2의 5번 항목을 작성합니다.)
```

### B-2. 검토 AI의 답변 형식

```
[검토 결과]
1. 범위: {내가 본 것 / 직접 대조하지 못한 것}
2. 항목별 판정
   | 항목 | 판정 | 이유·조건 | 근거(보고의 어느 부분) |
3. 방향 승인과 최종 승인을 구분: {방향 승인 / 최종 승인에 필요한 조건}
4. 충돌·위험: {앞서 받은 지시와 충돌하는 부분, 되돌리기 어려운 행동}
5. 다음 지시문 초안 — **사용자가 "요청함"으로 지정한 경우에만 작성**하고, 요청하지 않았다면 "요청 없음"이라고 쓴 뒤 생략합니다.
   (작성 시) 대상 AI, 범위, 하지 말 것, 보고 후 멈출 지점
```

### B-3. 지시문을 다른 AI에 전달할 때 (사용자 → 실행 AI)

```
[전달하는 지시문]
- 작성: {어느 AI / 사용자}, 검토: {어느 AI}
- 현재 유효한 이전 지시: {있으면 요약. 이 지시가 이전 지시를 대체하는지 명시}
- 범위: {지금 할 것} / 하지 말 것: {구현·커밋·push·유료 호출 등}
- 이 지시가 이전 중단·보류 지시와 충돌하면 **실행 전에 어느 쪽인지 되물어 주세요.**
- 보고 후 멈추고 다음 승인을 기다리세요.
```

## 쓰는 법 [권장]

1. 보고는 **요약하지 말고 원문**을 붙입니다. 요약하면 검토자가 요약의 오류까지 검토합니다.
2. 검토 AI가 **자기 시야의 한계**를 밝히게 합니다(원본 파일을 못 봤다면 "최종 검증"이라고 쓰지 않음).
3. 검토와 지시문 작성은 **다른 요청**입니다. 검토만 맡기면 검토 AI는 지시문을 쓰지 않고, 지시문 초안은 사용자가 요청한 경우에만 받습니다. 한 번에 **한 AI에게 한 가지 범위**만 지시합니다. 앞선 지시의 답이 오기 전에 새 지시를 보내지 않습니다.
4. 이전에 내린 **중단·보류 지시를 새 지시문에 함께 적습니다.** 같은 내용을 다시 말하지 않으면 새 지시문이 이전 지시를 덮어쓴 것으로 읽힙니다(MOEL AI 11-12, [05-chatgpt.md](../case-studies/moel-ai/05-chatgpt.md) E-1).
5. 검토 결과는 **검토자가 확인한 것만** 기록합니다. 다른 AI의 검증을 내가 한 것처럼 쓰지 않습니다.
