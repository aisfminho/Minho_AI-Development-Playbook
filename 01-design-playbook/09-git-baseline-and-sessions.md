# 09. Git 기준점과 세션 관리

## 목적

구현을 시작하기 전에 **되돌아올 수 있는 기준점**을 만들고, 여러 세션에 걸친 작업이 맥락을 잃지 않게 합니다.

## A. Git 기준점 절차 [권장]

각 단계를 **따로 승인**받습니다.

1. **로컬 커밋** — 승인된 파일 목록을 이름으로 하나씩 스테이징하고, 스테이징 목록이 승인 목록과 정확히 같은지 확인합니다. 공백 오류·민감정보를 다시 검사합니다.
2. **push** — 직전에 원격을 받아 와 예상하지 못한 새 커밋이 없는지 확인합니다. push 전 자동 배포 연결 여부를 확인합니다. 강제 push 금지.
3. **기준 태그** — 순서: 로컬 HEAD·로컬 main·원격 main이 같은 커밋인지 확인 → 같은 이름 태그가 로컬·원격에 없는지 확인 → annotated tag 생성 → 태그 push → **원격 태그가 가리키는 커밋 검증**. 덮어쓰기·강제 push 금지.
4. **인계 문서 갱신** — 태그 뒤 인계 문서의 상태를 갱신하고, 그 변경 커밋도 따로 승인받습니다.

**이미 올라간 이력은 다시 쓰지 않습니다.** 커밋 메시지를 바꾸고 싶다면 기존 커밋은 두고 다음 커밋부터 새 규칙을 적용합니다.

## B. 세션 관리 [권장]

1. **컨텍스트가 커지면 새 세션으로 넘어갑니다.** 넘어가기 전에 인계를 준비합니다.
2. **인계 문서 2종을 유지합니다.**
   - 프로젝트 상태 문서: 기술 스택·확정 결정, 완료 Step·테스트 결과, 진행 중 작업, 다음 Step, 미해결 문제·승인 대기, 바뀐 결정
   - 인계 문서: 다음 세션이 처음에 읽을 것, 하지 말아야 할 것, 첫 행동
3. **세션 시작·종료를 자동화합니다.** 예: 세션 시작 시 상태 확인 스킬, 작업 완료·세션 종료 시 인계 스킬. 자동화(Hook)는 실제로 동작하는지 시험 세션으로 확인합니다.
4. **AI 메모리에는 규칙과 이유를 남깁니다.** "무엇을" + "왜" + "어떻게 적용". 세션 ID를 출처로 남깁니다.
5. **대화 원본을 보관합니다.** 세션 JSONL과 보고 보관 파일은 나중에 방법론을 만들 근거입니다. 정기 정리 기간을 늘리거나 백업합니다.
6. **새 세션 시작 프롬프트를 정형화합니다**([templates/session-handoff-prompt.md](../templates/session-handoff-prompt.md)).

## 완료 기준

- [ ] 기준 태그가 원격에 있고, 가리키는 커밋을 검증했다
- [ ] 인계 문서가 현재 상태(커밋·push·태그)를 반영한다
- [ ] 새 세션이 인계 문서만 읽고 첫 행동을 정할 수 있다
- [ ] 세션 원본과 보고 보관 파일이 백업되어 있다

## 흔한 실패와 복구

| 실패 | 복구 |
|---|---|
| 인계 문서가 "커밋 승인 대기"처럼 옛 상태로 남음 | 지금 고치면 커밋 안 된 변경이 생기므로, 태그 뒤 한 번에 갱신하고 따로 커밋 승인 |
| 세션을 이어 붙일 때 관계가 불분명 | 인계 문서에 이전 세션 ID를 적음 |
| 병렬 작업 중 세션이 다시 시작되어 완료 알림을 놓침 | 결과 파일과 작업 트리 상태부터 확인하고 이어서 진행 |
