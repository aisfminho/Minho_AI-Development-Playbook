# 03. 의사결정 기록

## 목적

무엇을 골랐는지, 왜 골랐는지, **무엇이 바뀌었는지**를 한 곳에서 추적합니다. 여러 세션·여러 에이전트가 같은 결정을 보게 하는 단일 기준입니다.

## 절차 [권장]

1. **결정마다 ID를 붙입니다.** `D-001`부터 순서대로. 번호는 재사용하지 않습니다.
2. **상태를 명시합니다.**
   | 상태 | 뜻 |
   |---|---|
   | 확정 | 사용자가 승인함. 설계·구현의 기준 |
   | 목표·권장 | 방향은 정했지만 측정·승인 후 확정 |
   | 미확인(결정 전) | 아직 정하지 않음. **AI가 임의로 확정하지 않음** |
   | 대체됨 → D-0XX | 더 새 결정으로 바뀜. 삭제하지 않고 새 ID를 가리킴 |
3. **결정 전에 실측·비교합니다.** 후보별 장단점, 비용, 속도, 위험을 표로 만들고 추천안을 하나 붙입니다.
4. **질문은 묶어서 추천안과 함께 묻습니다.** [templates/question-bundle.md](../templates/question-bundle.md). 사용자는 항목별로 `승인 / 조건부 승인 / 변경 / 보류`로 답합니다.
5. **바뀐 결정은 조용히 고치지 않습니다.** 옛 결정에 "대체됨 → 새 ID"를 적고, 새 결정에 바뀐 이유를 적습니다.
6. **감사 결과도 결정으로 연결합니다.** 독립 감사가 결정을 더 구체화하면 새 결정 번호(또는 하위 번호)로 기록합니다.
7. **위험한 결정은 코드 스위치로 연결합니다.** 외부 전송·유료 호출처럼 되돌리기 어려운 결정은 기본값을 꺼 둔 설정값으로 구현하게 합니다.
8. **문서 우선순위 규칙도 결정입니다.** "최신 결정 → 현재 설계 → 과거 자료" 규칙 자체를 결정으로 남깁니다.
9. **제안자·실행자·검증자·결정자를 구분해 적습니다.** 여러 AI가 관여하면 "누가 제안했나"와 "누가 결정했나"가 갈립니다. AI의 제안이 바뀐 이유(사용자 이의, 외부 확인)도 함께 남깁니다. ChatGPT가 처음 Streamlit을 권했다가 사용자 이의로 Vue 3 + FastAPI로 바꾼 사례처럼, 최초 제안이 최종 결정이 아닌 경우가 많습니다.
10. **수치에는 처리 단계를 붙입니다.** "13,597행"(원시), "11,380행"(전처리 후)처럼 단계 이름 없는 숫자는 서로 다른 값이 충돌하는 것처럼 보입니다.

## 완료 기준

- [ ] 모든 결정에 ID·상태·날짜·근거가 있다
- [ ] "대체됨" 결정은 새 ID를 가리키고, 새 결정은 바뀐 이유를 적었다
- [ ] "미확인" 결정이 설계 문서에 확정처럼 쓰인 곳이 없다(모델명·요금·성능·일정)
- [ ] 다른 문서는 결정을 복사하지 않고 ID로 참조한다

## 흔한 실패와 복구

| 실패 | 복구 |
|---|---|
| 같은 결정이 여러 문서에 다르게 적힘 | 결정 기록을 단일 기준으로 정하고 나머지는 ID 링크로 바꿈 |
| 결정 ID가 보고서마다 다르게 인용됨 | 결정 기록 원본에서 ID와 제목을 다시 확인(아래 D-024/D-027 사례) |
| 미확정 사항이 확정처럼 퍼짐 | 서브에이전트 감사 항목에 "확정 안 됐는데 확정처럼 쓴 것"을 넣음 |
| 같은 자료의 다른 수치가 충돌로 보임 | 원시·정제·최종 사용 단계로 나눠 표로 기록하고, 정정된 옛 수치는 "이전 실행본"으로 표시(D-012) |
| AI의 제안이 "합의된 결정"처럼 읽힘 | 결정 기록에 "사용자 승인" 날짜와 승인 방식을 적고, AI 제안만 있는 항목은 "권장"으로 표시 |

## MOEL AI 근거

**상태 관리** [사실]
- 결정 `D-001`~`D-036`, 상태는 확정 / 대체됨 / 목표·권장 / 미확인 등 [보고서]. 결정 기록에는 "임의로 확정하지 않을 것"이라는 별도 절이 있었습니다 [보고서].
- 프로젝트 헌장 문서에도 "모델, 과금·배포 구체 구성은 결정 전이다. 임의로 확정하지 않는다"가 적혀 있었습니다(`d39ff7ed:148`).

**지우지 않고 대체한 사례**
- 로컬 LLM·임베딩 결정(D-014·D-015, D-201·D-202) → OpenAI API·Vercel+Railway(D-018·D-019). 이전 결정은 "대체됨"으로 보존 [보고서].
  - 배경 [사실]: Claude의 최종 권장은 "맥북 로컬 + Gemma 4 26B-A4B + KURE-v1, 배포는 선택 사항"(`d39ff7ed:541`). 사용자는 지도교수 답변 뒤 "OpenAI API 기반 … Vercel + Railway 방식"으로 확정(`d39ff7ed:1164`).
- 법령 자료원: D-024(법령 RAG를 범위에 포함, 처음에는 법제처 Open API 기준, `44d22df7:827`) → **D-027(국가법령정보센터 공식 PDF를 사용자가 직접 내려받아 사용, 최종)**(`44d22df7:1201`, `:1213`). [사실]
- 시행일 기준: D-028("표시하는 날" 기준) → Codex AUD-12 → D-034 ④("처리 기준일"로 통일)(`09fb2455:630` 상태표 12행). [사실]

**여러 AI가 관여한 결정의 경로** [사실, v0.2 보완 — 상세는 [05-chatgpt.md](../case-studies/moel-ai/05-chatgpt.md)]
- Streamlit → Vue 3 + FastAPI: ChatGPT 최초 제안(Streamlit) → 사용자 질문 3개(속도·차별화·대안) → ChatGPT 입장 변경 → 지도교수 확인 → 확정(`gpt:6aed9c1d/7f4ebb09`, `/bbb21220`, `/bbb212c5`, `/32d45a01`, `/bbb215d8`, `/e2e3be0a`). Claude Code 기록에는 결과만 남음(`d39ff7ed:313`).
- 로컬 LLM → OpenAI API: ChatGPT가 로컬을 권했다가 "100건 일괄 시연을 보장하지 못한다"며 철회, 사용자의 "배포해서 URL이 있어야 해"와 지도교수 답변, AI-Hub 이용 조건의 외부 확인을 거쳐 11-12 10:56 확정(`gpt:6aed5ec8/6889ece4`, `/58b48e16`, `/eb75c0ca`, `/d1917ebe`, `/1cf3014b`). ChatGPT의 "허용 어렵다" 판단은 사용자의 외부 확인이 뒤집었습니다.
- 데이터 수치: 13,597행(원시) → 빈 값 2,175·중복 42 제거 → 11,380행(전처리), 원시 원본이 로컬에 없어 D-013으로 "11,380행으로 1차 인덱스, 재수집 보류"(`d39ff7ed:184`, `:346`, `44d22df7:61`).
- ID 대응: D-014·015(로컬 LLM) → D-018·019·020(OpenAI, 외부 전송 허용 확인)은 [보고서]이며, 시각상 ChatGPT 결정(10:56)과 Claude Code 전달(10:58:24, `d39ff7ed:1164`)이 이어집니다.
