# 03. 의사결정 기록

## 목적

무엇을 골랐는지, 왜 골랐는지, **무엇이 바뀌었는지**를 한 곳에서 추적합니다. 여러 세션·여러 에이전트가 같은 결정을 보게 하는 단일 기준입니다.

## 절차 [권장]

1. **결정마다 ID를 붙입니다.** `D-001`부터 순서대로. 번호는 재사용하지 않습니다.
2. **상태를 명시합니다.**
   | 상태 | 뜻 |
   |---|---|
   | 확정 | 사용자가 승인함. 설계·구현의 기준 |
   | 목표·권장 | 방향은 정했지만 측정·승인 후 확정 |
   | 미확인(결정 전) | 아직 정하지 않음. **AI가 임의로 확정하지 않음** |
   | 대체됨 → D-0XX | 더 새 결정으로 바뀜. 삭제하지 않고 새 ID를 가리킴 |
3. **결정 전에 실측·비교합니다.** 후보별 장단점, 비용, 속도, 위험을 표로 만들고 추천안을 하나 붙입니다.
4. **질문은 묶어서 추천안과 함께 묻습니다.** [templates/question-bundle.md](../templates/question-bundle.md). 사용자는 항목별로 `승인 / 조건부 승인 / 변경 / 보류`로 답합니다.
5. **바뀐 결정은 조용히 고치지 않습니다.** 옛 결정에 "대체됨 → 새 ID"를 적고, 새 결정에 바뀐 이유를 적습니다.
6. **감사 결과도 결정으로 연결합니다.** 독립 감사가 결정을 더 구체화하면 새 결정 번호(또는 하위 번호)로 기록합니다.
7. **위험한 결정은 코드 스위치로 연결합니다.** 외부 전송·유료 호출처럼 되돌리기 어려운 결정은 기본값을 꺼 둔 설정값으로 구현하게 합니다.
8. **문서 우선순위 규칙도 결정입니다.** "최신 결정 → 현재 설계 → 과거 자료" 규칙 자체를 결정으로 남깁니다.

## 완료 기준

- [ ] 모든 결정에 ID·상태·날짜·근거가 있다
- [ ] "대체됨" 결정은 새 ID를 가리키고, 새 결정은 바뀐 이유를 적었다
- [ ] "미확인" 결정이 설계 문서에 확정처럼 쓰인 곳이 없다(모델명·요금·성능·일정)
- [ ] 다른 문서는 결정을 복사하지 않고 ID로 참조한다

## 흔한 실패와 복구

| 실패 | 복구 |
|---|---|
| 같은 결정이 여러 문서에 다르게 적힘 | 결정 기록을 단일 기준으로 정하고 나머지는 ID 링크로 바꿈 |
| 결정 ID가 보고서마다 다르게 인용됨 | 결정 기록 원본에서 ID와 제목을 다시 확인(아래 D-024/D-027 사례) |
| 미확정 사항이 확정처럼 퍼짐 | 서브에이전트 감사 항목에 "확정 안 됐는데 확정처럼 쓴 것"을 넣음 |
