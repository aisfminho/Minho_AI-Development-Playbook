# 06. 승인 절차

## 목적

AI가 사용자 승인 없이 다음 단계로 넘어가거나, 되돌리기 어려운 행동을 하지 않게 합니다. 동시에 **불필요한 중간 질문은 줄여** 속도를 유지합니다.

## 절차 [권장]

### 1) Step 단위 승인

```
Step 계획 제시 → "STEP-XX 시작 승인" → (구현·TDD·독립 리뷰) → 결과 + 검증 방법 보고
  → "STEP-XX 완료 승인" → 다음 Step의 **계획만** 제시
  → 또는 "STEP-XX 반려" → 수정 후 재보고
```

- AI는 어떤 경우에도 승인 없이 다음 Step으로 넘어가지 않습니다. 자동으로 이어지는 스킬·워크플로 안에서도 Step 경계에서 멈춥니다.
- 설계 단계 자체도 하나의 Step(예: STEP-01 설계)으로 다룹니다.
- 설계에서 구현으로 넘어갈 때는 **설계 Step 완료 승인 → 구현 전 기준 태그 → 첫 구현 Step 시작 승인**을 각각 따로 받습니다. 하나의 승인으로 합치지 않습니다. (MOEL AI는 태그를 먼저 만들었고, 그 시점에 STEP-01 완료 승인은 대기 중이었습니다 — `fc1439ba:870`)

### 2) 완료 조건 중심 운영

- 날짜별 일정보다 **Step의 완료 조건**을 기준으로 진행합니다. 완료되면 바로 다음 Step 계획을 제시합니다.
- 서로 독립적인 Step은 묶어서 한 번에 승인할 수 있습니다.
- Step 내부의 구현·테스트·리뷰는 자율적으로 진행하고, 중요한 기술 변경·유료 호출·범위 변경만 묻습니다.

### 3) 별도 승인이 필요한 행동 (각각 따로)

| 행동 | 승인 전 AI가 보고할 것 |
|---|---|
| 최초 유료 API 호출 | 모델, 예상 비용, 외부로 보내는 데이터 |
| 데이터 재수집·외부 요청 | 대상, 이유, 대안 |
| 외부 배포 | 배포 대상, 자동 배포 연결 여부 |
| commit / push / tag | 대상 파일 목록, 민감정보 검사 결과 |
| 이미 올라간 이력 변경 | **기본은 하지 않음.** 대신 이후 규칙을 바꿈 |
| 원문·개인정보 출력 | 기본 금지, 집계만 |

### 4) 질문하는 법

- 질문은 **묶어서, 추천안과 함께** 냅니다([templates/question-bundle.md](../templates/question-bundle.md)). "추천대로면 '전부 추천'이라고만 답해 주세요"처럼 응답 비용을 낮춥니다.
- 사용자는 `승인 / 조건부 승인(조건) / 변경(내용) / 보류`로 답합니다.

### 5) 보고 채널

- 긴 지시는 요청 파일(예: `message.md`)로, 긴 보고는 응답 파일(예: `respond.md`)로 주고받고, 대화창에는 요약만 둡니다.
- 응답 파일에는 **최신 보고만** 두고, 이전 보고는 보관 폴더로 옮깁니다(삭제 금지). 이전 보고에만 남은 결정 원문이 있을 수 있습니다.
- 소통 파일은 Git에 올리지 않습니다.

### 6) 도구 범위 최소화

- 새 스킬·훅을 늘리기보다 기존 도구를 먼저 씁니다. 이미 있는 명령을 다시 만들지 않습니다.

## 완료 기준

- [ ] 헌장 문서에 승인 명령어 3종(시작·완료·반려)과 자동 진행 금지가 적혀 있다
- [ ] 별도 승인 행동 목록이 있다
- [ ] 보고 채널(요청·응답·보관 파일)이 정해져 있다
- [ ] Step 목록에 각 Step의 완료 조건이 있다

## 흔한 실패와 복구

| 실패 | 복구 |
|---|---|
| "진행해 줘"를 다음 Step 승인으로 해석 | 승인 명령어를 정확한 문자열로 정하고, 그 외 표현은 확인 질문 |
| 보고가 덮어써져 이전 결정 원문이 사라짐 | 응답 파일 교체 전 보관 폴더로 옮기기 |
| 도구가 너무 많아 관리 비용 증가 | 유지할 도구만 남기고 나머지는 제거 |

## MOEL 전용 설정

- 승인 명령어: `STEP-XX 시작 승인` / `STEP-XX 완료 승인` / `STEP-XX 반려`
- 소통 파일: `message.md`(사용자 → Claude), `respond.md`(Claude → 사용자), `codex_only_requests.md` / `codex_only_respond.md`(사용자 ↔ Codex)
- 커밋 메시지 제목: `YYYY-MM-DD HH:MM`, 세부는 본문(→ [09단계](09-git-baseline-and-sessions.md))
