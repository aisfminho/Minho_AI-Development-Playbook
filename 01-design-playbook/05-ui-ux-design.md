# 05. UI/UX 설계

## 목적

화면이 **기술 계약과 실제 데이터에 정직한지**, 그리고 사용자가 원하는 시각적 정체성을 갖췄는지를 따로 확인하며 설계합니다.

## 절차 [권장]

1. **기술 승인과 시각 승인을 나눕니다.** "설계 방향 승인"과 "최종 시각 디자인 확정"은 다른 승인입니다. 목업을 직접 보기 전에는 시각 디자인을 확정하지 않습니다.
2. **목업을 두 형식으로 만듭니다.** 외부 의존성 없이 열리는 인터랙티브 HTML + 화면별 PNG(데스크톱·모바일). **합성 예시 데이터만** 쓰고 실제 데이터·접근 키는 넣지 않습니다.
3. **화면의 모든 수치·계층을 데이터로 입증합니다.**
   - 수치: 정의·분모·출처가 있어야 표시(→ [02단계](02-data-verification.md))
   - 계층: 데이터에 있는 칸만 표시. 없는 계층을 추측해 만들지 않음
   - 진행률: 실제 행 수·상태로만 표시. 가짜 진행 상황 금지
   - 행 수 일관성: `전체 행 = 입력 오류 행 + 처리 대상`, 진행률 분모는 처리 대상
4. **UI 단계와 이벤트 계약을 매핑합니다.** 화면 단계 표시와 서버 이벤트 종류의 대응표, 실패·중단 상태 표현을 명시합니다.
5. **합성 시연과 실제 AI 결과를 구분해 표시합니다.**
6. **구현되지 않은 기능을 구현된 것처럼 보이지 않게 합니다.** (예: 탐지하지 않는 개인정보 유형)
7. **사용자 고유 결정은 자리표시로 둡니다.** 브랜드명·핵심 문구는 `[제품명]`으로 두고 후보만 제안합니다. 최종 화면에는 자리표시가 남지 않게 합니다.
8. **차별화 요구는 "과정 자체의 시각화"로 풀어 봅니다.** 흔한 SaaS 템플릿(그라데이션, 반복 카드, 장식용 AI 그래픽) 대신 제품의 처리 과정을 시각 언어로 씁니다.
9. **고급 연출은 핵심 기능과 분리합니다.** 애니메이션·영상은 핵심 기능 일정과 성능에 영향을 주지 않는 독립 구성으로 둡니다.

## 완료 기준

- [ ] HTML 목업과 화면별 PNG가 있고 합성 데이터만 쓴다
- [ ] 화면의 수치·계층·진행률이 모두 실제 데이터 또는 계약으로 설명된다
- [ ] UI 단계 ↔ 이벤트 매핑표가 있다
- [ ] 기술 승인과 시각 승인이 각각 기록되었다

## 흔한 실패와 복구

| 실패 | 복구 |
|---|---|
| 데이터에 없는 조직 계층을 그럴듯하게 표시 | 실제 데이터의 칸만 표시하도록 규칙화하고, 그 규칙을 검증 |
| 통계 문구가 실제 의미와 다름 | 정의·분모·출처를 다시 적고 문구 수정 |
| 시안이 흔한 템플릿처럼 보임 | 제품 고유의 처리 과정을 시각 요소로 정의(시그니처 요소) |

## MOEL AI 근거 [사실]

- **차별화 요구:** "현재 제시된 A/B 업무 화면 디자인만으로는 다른 AI 기반 프로젝트와 충분히 차별화되지 않을 가능성 … 흔한 그라데이션, 반복적인 카드 배치, 의미 없는 장식용 AI 그래픽 지양"(`79503ed4:1052`).
- **과정의 시각화 승인:** "민원 처리 과정 자체를 고유한 시각 언어로 만들겠다는 제안에 동의"(`79503ed4:1074`). 시그니처 요소: Dossier, Redaction, Stage Rail, Batch Grid, Evidence Thread, Org Path.
- **지어낸 계층 금지:** "Org Path는 실제 데이터에 존재하는 부서 계층만 표시하며, 없는 계층을 추측해 생성하지 않도록"(`79503ed4:1074`). → 결정 D-034 ⑦: 담당업무 데이터의 기관명·부서명만, 계층·지청 추측 금지(`09fb2455` 서브에이전트 `a2579273:161`).
- **가짜 진행 금지:** "Batch Grid는 실제 행 수와 상태에 따라 표시하고, 가짜 진행 상황을 만들어서는 안 됩니다"(`79503ed4:1074`).
- **수치·매핑·행 수 점검 요구:** 79.6%의 의미·계산 기준·표본 수·출처, Stage Rail 8단계 ↔ SSE 이벤트 10종 매핑, "97행 중 입력 오류 3행이라면 94행이 처리 대상"(`79503ed4:1174`).
- **승인 분리:** "이번에 승인한 것은 설계 방향이며, 최종 시각 디자인의 확정은 아닙니다"(`79503ed4:1174`). 목업은 HTML + 1440px PNG + 390px 모바일 PNG, 합성 데이터만.
- **자리표시:** "설계 문서와 목업에서는 [제품명] 자리표시를 사용해도 좋습니다. 실제 사용자에게 제공하는 최종 화면에는 자리표시가 남지 않도록"(`79503ed4:1074`).
- **미구현 기능 표시 금지:** "이름·주소 등 지원하지 않는 탐지 기능을 구현된 것처럼 표시하지 않습니다"(`55b37226:385`).

## MOEL 전용 설정

- 흐름: 공개 랜딩 `/` → 접근 키 확인 `/access` → 업무 워크벤치 `/single`, `/batch`(`79503ed4:1052`)
- 테마: 랜딩 다크, 업무 화면 라이트, 테마 전환 초기 필수 아님(`79503ed4:1074`)
- 업무 화면 방향: A+ (A안 Precision Mono + 처리 과정 시각화)
- 새로고침 복구: 최근 결과 ID만 `sessionStorage`(AUD-26)
