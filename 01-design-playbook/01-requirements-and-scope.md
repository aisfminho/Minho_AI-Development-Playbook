# 01. 요구사항·범위·작업 모드 합의

## 목적

무엇을 왜 만드는지, 어디까지 만드는지, 그리고 **지금이 설계 단계인지 구현 단계인지**를 사용자와 AI가 같은 말로 이해하게 합니다.

## 절차 [권장]

1. **목적을 한 문장으로 정합니다.** 예: "장기 운영 상용 서비스가 아니라, 기말 발표에서 안정적으로 시연하는 프로젝트."
   - 이후 모든 범위 질문(보안 수준, 정확도 목표, 배포 방식, 일정)을 이 문장에 비춰 판단합니다.
2. **기존 자료를 모으고 우선순위를 정합니다.**
   - 기본 순서: `최신 확정 결정 → 현재 설계 문서 → 과거 자료(과제·초기 기획)`
   - 예외: **측정 수치와 전처리 결과는 원본 자료와 실제 파일로 검증**합니다.
3. **AI가 먼저 불일치·누락을 보고하게 합니다.** 구현 전에 "현재 설계 문서와 과거 자료 사이의 불일치"를 목록으로 받습니다.
4. **작업 모드를 헌장 문서에 적습니다.** 예: `현재 단계: 설계. 코드·의존성 변경 금지. 구현은 "STEP-XX 시작 승인" 이후.`
5. **기능 목록은 계획의 입력으로 다룹니다.** "나머지 개발을 진행해 주세요"처럼 들리는 지시도, 설계가 확정되지 않았다면 AI는 "설계 확정인지, 구현 착수인지"를 먼저 확인합니다.
6. **보류 항목을 좁게 정합니다.** 외부 답변이 필요한 것만 보류하고 나머지 설계는 진행합니다.
7. **범위 밖 항목을 명시합니다.** "하지 않을 것" 목록이 있어야 과설계가 줄어듭니다.

## 완료 기준

- [ ] 목적 한 문장과 핵심 시연·사용 시나리오가 문서에 있다
- [ ] 문서 우선순위 규칙이 결정 기록에 있다
- [ ] 과거 자료와의 불일치 목록이 보고되었고, 각 항목의 처리 방향이 정해졌다
- [ ] 헌장 문서에 현재 작업 모드와 구현 시작 조건이 적혀 있다
- [ ] 보류 항목과 범위 밖 항목이 따로 적혀 있다

## 흔한 실패와 복구

| 실패 | 복구 |
|---|---|
| AI가 설계 확정 전에 구현을 시작함 | 즉시 중단 → **지금까지 만든 것, 테스트 수, 하지 않은 것**을 표로 보고 → 그 코드를 "초안으로 둘지, 기반으로 쓸지"를 사용자가 결정 → 헌장 문서에 작업 모드 기록 |
| 과거 자료가 최신 결정을 덮어씀 | 문서 우선순위 규칙을 결정으로 기록(아래 D-009 사례) |
| 범위가 계속 넓어짐 | 목적 문장을 다시 꺼내 항목별로 "최소 / 제외"를 정함 |

## MOEL AI 근거

**설계 전 구현 선행 (숨기지 않는 사실)** [사실]
- 사용자는 "최종 LLM 실행 방식과 배포 환경만 보류하고, 나머지 프로젝트 개발을 진행"하겠다고 지시했습니다(`d39ff7ed:748`). Claude는 이를 구현 지시로 해석했습니다.
- 그 결과 개발 환경과 테스트 17건(`d39ff7ed:745`) → 단건 엔진(Mock LLM + 합성 데이터), 스키마·검색·분류·추천·초안·SSE·검토 API, **테스트 45건**(`d39ff7ed:1160`)이 만들어졌습니다.
- 사용자 1차 중단: "아직 구현은 하지 마 설계 계획부터 확정지어야해"(`d39ff7ed:1149`). Claude는 중단 시점의 상태를 표로 보고하고 코드 처분을 질문했습니다(`d39ff7ed:1160`).
- OpenAI 방식 확정(`d39ff7ed:1164`) 뒤 Claude는 다시 "다음 미완료 단계를 구현"하겠다고 했고(`d39ff7ed:1167`), 로컬 LLM 코드를 정리하며 테스트가 41건이 되고 프론트 일부 모듈(디자인 토큰, API 타입·클라이언트, SSE 상태 함수와 테스트)이 추가되었습니다.
- 사용자 2차 중단 뒤 Claude는 "구현을 멈추고, 지금부터는 대화하면서 설계와 계획부터 정하겠습니다"라고 답했습니다(`d39ff7ed:1386`). 2차 중단의 사용자 문장은 프로젝트 메모리에 "내랑 대화하면서 설계 및 계획부터 할꺼야"로 기록되어 있습니다(memory `design-before-implementation.md`, 해당 JSONL 줄의 텍스트는 [미확인]).
- 이후 규칙: 설계 우선, Step 시작·완료 승인(D-021). 재사용 교훈은 **"실행 전 범위·승인 확인"**입니다.

**문서 우선순위** [사실]
- 사용자: "주차별 과제 내용이 무조건 최신 설계보다 우선하도록 만들지는 않는 것이 좋아 … 최신 확정 결정(DECISIONS.md) → 현재 개발 설계 문서 → 주차별 과제의 과거 설계. 단, 실제 측정 수치와 전처리 결과는 과제 원본 및 데이터 파일을 기준으로 검증"(`d39ff7ed:313`). → D-009.

**목적 재정의로 범위 축소** [사실]
- "장기 운영용 상용 서비스가 아니라 대학원 기말 발표를 위한 프로젝트 … 개발 복잡도를 최소화"(`d39ff7ed:496`)
- 개인정보: "기업용 보안 시스템을 구축하기보다 개인정보 보호 가드레일이 작동하는 과정을 시각적으로 보여주는 것을 우선"(`55b37226:322`)
- 평가: "최우선 목표는 상용 수준의 추천 정확도 확보가 아니라 … 안정적으로 시연하는 것"(`fc1439ba:193`)

**보류는 좁게** [사실]
- LLM 실행 방식과 배포 환경만 지도교수 답변 대기로 보류하고 나머지는 진행(`d39ff7ed:748`). 답변 후 확정(`d39ff7ed:1164`).
